# Role ownership matrix

Who owns which capability across Agent, Supervisor, QA Manager, Operation Manager and Super Admin in the QA module.

## Purpose

The mock currently gives the Supervisor and the QA Manager almost identical pages. Several capabilities overlap: both can create alert rules that hit the same agents, both can edit each other's rules, both can schedule coaching for the same agent, and the Operation Manager and the QA Manager both change team membership. This matrix lists every configurable capability, what the mock does today per role, where two roles overlap, the open question, a proposal to start the discussion, and an empty Decision column for the meeting.

Generated from the mock on 2026-10-21. The proposals are a starting point, not a decision.

## How to use it in the meeting

1. Go section by section. Start with the rows marked **Overlap: High**.
2. For each row read **Scope today**, then the **Overlap**, then the **Open question**.
3. Discuss the **Proposal** and record the **Decision** (which role owns it, or "shared", or "not needed") and any note.
4. Rows with Overlap "None" are there for completeness; confirm them quickly.
5. The shareable page version of this matrix lets everyone record decisions in place.

## Legend

| Code  | Meaning                                                       |
| ----- | ------------------------------------------------------------- |
| **O** | Owns: creates and configures it                               |
| **E** | Can edit items created by another role                        |
| **A** | Acts: performs the action (open, acknowledge, resolve, award) |
| **V** | Views only                                                    |
| **R** | Receives / is affected by it                                  |
| —     | No access                                                     |

Roles: Agent · S = Supervisor · QAM = QA Manager · OM = Operation Manager · SA = Super Admin.

Personas in the mock: SUP-001 Maria García (Team 1), QAM-001 Elena Ruiz, OPM-001 Sofía Navarro, AGT-004 John Smith.

## Known mock inconsistencies to fix (for developers)

1. `TriggersPage` stamps QAM rules as "Laura Gómez" (SUP-003's name); the QAM persona is Elena Ruiz.
2. The Supervisor's trigger agent picker lists every agent; the `supervisorIds=['SUP-001']` default is not enforced.
3. `roleFromPath` knows only supervisor and qa-manager; the Operation Manager reaches QA Manager pages and is recorded as `QA_MANAGER`.
4. The legacy `/qa/qamanager/disputes` path is scoped as agent.
5. QA Manager Settings and Super Admin Global config keep separate scales and emotion mappings.
6. `getSuperAdminNavigation()` is never rendered; the Super Admin Coaching and LMS entries open a placeholder.
